# E7-17 Optional Table Refinement Pass Design

## Goal

Add an optional second pass for table proposals that mirrors the callout review workflow: detect candidate tables, render a reviewable PDF, allow revise/update, then resume prep with finalized table decisions.

## Scope

This design is limited to the prep-side table refinement flow for `gmkit analyze-and-prep-pdf`.

Included:
- the existing code-first table discovery remains the primary pass
- refinement only applies to table proposals that need manual or agent-assisted cleanup
- table annotations use a distinct visual cue from callouts; the table annotation color should be cyan while callouts remain unchanged
- the workflow exposes one shared reviewable PDF output before any handoff pause
- a single revise/update command persists finalized decisions for both tables and callouts into machine-readable prep artifacts
- prep can resume from the refined artifacts so downstream conversion consumes the finalized table contract
- the implementation should compare the current table flow against the callout flow and only add missing pieces

Excluded:
- redesigning the underlying table detection heuristics
- changing TOC generation
- changing the callout refinement workflow
- changing conversion behavior beyond consuming finalized prep artifacts
- introducing a new agent capability model beyond the existing prep-side handoff shape

## Canonical Flow

The intended table refinement flow mirrors the callout work:

1. prep detects candidate tables and records proposal artifacts
2. prep renders one annotated review PDF that includes both table and callout proposals
3. the user reviews the single PDF and adjusts table geometry if needed
4. the revise step writes finalized artifacts for both tables and callouts
5. prep resumes and writes the authoritative contracts for downstream use
6. conversion consumes the finalized table contract rather than rediscovering tables

The key design requirement is alignment: the table workflow should feel like the callout workflow, not like a separate one-off implementation.

## Architecture

The table refinement flow should preserve three responsibilities:
- code detects table candidates and produces raw proposal evidence
- the prep workflow renders reviewable artifacts before pause/resume
- the resume path finalizes table decisions and makes them available to conversion

The workflow needs an explicit handoff boundary:
- the review PDF must exist before pause
- the revise artifact must be machine-readable
- resume should consume the revise artifact without re-running table detection
- if the refined artifact is absent, the workflow should keep the raw proposal geometry and continue deterministically

## Artifact Flow

The table flow should use the same general artifact layering as callouts:
- raw table proposals remain the source evidence
- a reviewable annotated PDF is produced for manual inspection alongside the callout annotations
- a revised/refined table artifact captures the final geometry or table decisions
- the resolved prep guidance artifact becomes the downstream contract for conversion

The exact filenames should remain aligned with existing prep conventions unless a mismatch with callout naming is found during comparison.

## User Experience

From the user’s perspective:
- prep produces one reviewable PDF for both table and callout proposals
- the user can visually inspect and edit the PDF
- the revise/update command captures their corrections once
- conversion later consumes the finalized table decisions without re-running discovery

The user should not need to edit raw JSON manually.

## Testing Strategy

E7-17 should prove:
- table proposals are still generated by code in the first pass
- the shared review PDF is created before any pause boundary
- the revise/update command can finalize both table and callout decisions in one pass
- resume applies the refined table artifact
- conversion consumes the refined result when present
- the raw proposal path still works when refinement is skipped

## Acceptance Outcome

E7-17 is complete when table handling in prep follows the same reviewable handoff pattern as callouts and conversion uses the finalized table contract rather than discovering tables itself.
